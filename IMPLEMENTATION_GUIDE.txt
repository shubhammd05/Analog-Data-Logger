PROJECT OVERVIEW
════════════════════════════════════════════════════════════════════════════

A dual-core ESP32 data logger with:
- 4 independent ADC channels with configurable sampling rates
- RTC timestamping for accurate data logging
- Dual file group system (A/B) for continuous operation
- WiFi AP mode for data retrieval and configuration
- Concurrent SD access using mutex protection
- Power-efficient operation with CPU frequency scaling and light sleep
- Interrupt-based monitoring (button, SD space check)

HARDWARE COMPONENTS
════════════════════════════════════════════════════════════════════════════

✓ ESP32 DevKit V1
✓ DS3231 RTC module (I2C)
✓ MicroSD card module (SPI)
✓ RGB LED (common cathod) for status
✓ Push button for AP mode trigger
✓ 4x analog sensors (represented by potentiometers)
✓ 3x 1000Ω resistors for LED current limiting

INSTALLATION STEPS
════════════════════════════════════════════════════════════════════════════

1. UPLOAD FILESYSTEM (LittleFS)
   - Place data_page.html, parameters.html in data/ folder
   - Run: pio run --target uploadfs

3. COMPILE AND UPLOAD
   - Run: pio run --target upload
   - Monitor: pio device monitor -b 9600

SYSTEM OPERATION
════════════════════════════════════════════════════════════════════════════

BOOT SEQUENCE
─────────────────────────────────────────────────────────────────────────────
1. Initialize RTC → Check I2C communication
2. Initialize LittleFS → Load web files
3. Initialize SD card → Check SPI communication
4. Create/verify 8 log files (LOG_01 to LOG_08)
5. Red LED turns ON (initialization in progress)
6. If all OK: Green LED ON → System ready
7. If any fail: Red LED stays ON → System halts
8. Start dual-core tasks:
   - Core 1: Logging task (ADC sampling + SD writing)
   - Core 0: AP monitor task (WiFi handling)
9. Begin continuous logging to Group A (LOG_01-04)

NORMAL OPERATION
─────────────────────────────────────────────────────────────────────────────
→ Green LED ON
→ CPU @ 80MHz (power saving)
→ All 4 channels sample at configured rates
→ Data written to Group A files with timestamps
→ Light sleep between samples if rate > 1000ms
→ SD space checked using total Estimate
→ If half of sd card space is used then LED turns Yellow
→ If total space is filled i.e. no space for logging then logging stops and LED shows magenta (flickering)

BUTTON PRESS (AP MODE ACTIVATION)
─────────────────────────────────────────────────────────────────────────────
1. User presses button (GPIO2)
2. Interrupt triggers → uploadButtonPressed flag set
3. File group swap:
   - Close current log files
   - Toggle group (A↔B)
   - Group A → Transmission state
   - Group B → Logging state (NEW data goes here)
4. Start WiFi AP:
   - CPU scales to 240MHz
   - AP: "ESP32-DataLogger" / Password: "DataLog2024!"
   - IP: 192.168.4.1
   - DNS server for captive portal
5. Concurrent operation:
   - Core 1: Continue logging to Group B (with mutex)
   - Core 0: Serve Group A files via web interface (with mutex)
6. Client can:
   - View/download CSV files from Group A
   - Update channel configurations
   - View real-time data dashboard

AP TIMEOUT/DISCONNECT
─────────────────────────────────────────────────────────────────────────────
→ AP stops after 5 minutes OR all clients disconnect (whichever first)
→ Transmission group (Group A) files truncated to 0 bytes
→ If DEBUG=1, CSV headers rewritten after truncation
→ WiFi disconnected, CPU scales back to 80MHz
→ System returns to normal logging state

SD CARD FULL
─────────────────────────────────────────────────────────────────────────────
→ LED turns to Megenta (flickering)
→ Logging pauses (task continues but skips writes)
→ System waits for space to free up
→ When space available: Green LED ON → Resume logging

LED STATUS REFERENCE
════════════════════════════════════════════════════════════════════════════

RED     → Initialization failed (RTC/SD error)
          System halted, check hardware connections

GREEN   → Normal operation
          Logging active, SD card OK, all systems operational

Yellow  → SD card half full
          Logging still active

Megenta (flickering)  → SD card full
                      Logging paused, waiting for space
                      Free up space or replace SD card

LED OFF  → No power connected
            the circuit is  off

BLUE  → AP is active 
        logging is ON on core 1, AP mode active on core 0, both are not interfearing with each other using mutex

CSV FILE FORMAT
════════════════════════════════════════════════════════════════════════════

Header (if DEBUG=1):
year,month,date,day,hour,minutes,second,milliseconds,value

Data rows:
2025,12,31,2,14,30,45,11,2048
2025,12,31,2,14,31,45,12,2051
...

Fields:
- year: 4-digit year
- month: 1-12
- date: 1-31
- day: 0-6 (Sunday=0)
- hour: 0-23
- minutes: 0-59
- second: 0-59
- milliseconds: 0-59
- value: ADC reading (0-4095 for 12-bit)

FILE GROUP SYSTEM
════════════════════════════════════════════════════════════════════════════

Group A: LOG_01.csv, LOG_02.csv, LOG_03.csv, LOG_04.csv
Group B: LOG_05.csv, LOG_06.csv, LOG_07.csv, LOG_08.csv

Mapping:
- Channel 1 → LOG_01 (Group A) or LOG_05 (Group B)
- Channel 2 → LOG_02 (Group A) or LOG_06 (Group B)
- Channel 3 → LOG_03 (Group A) or LOG_07 (Group B)
- Channel 4 → LOG_04 (Group A) or LOG_08 (Group B)

Operation:
1. Boot → Group A = Logging, Group B = Idle
2. Button press → Swap → Group B = Logging, Group A = Transmission
3. AP serves Group A while Group B logs new data
4. AP stops → Group A truncated, Group B continues logging
5. Next button press → Swap again

POWER CONSUMPTION ESTIMATE
════════════════════════════════════════════════════════════════════════════

Logging Mode (WiFi OFF):
- CPU @ 80MHz: ~80-100mA
- With light sleep (1Hz sampling): ~40-60mA average
- SD card writes: +20mA bursts

WiFi AP Mode:
- CPU @ 240MHz: ~150-200mA
- Active WiFi transmission: ~200-300mA
- Duration: Max 5 minutes

Battery Life Estimate (for 2000mAh battery):
- Continuous logging (no sleep): ~20 hours
- With light sleep (1Hz): ~30-40 hours
- With periodic AP mode (5min every hour): ~25-35 hours

TROUBLESHOOTING
════════════════════════════════════════════════════════════════════════════

ISSUE: Red LED stays on after boot
FIX: Check connections:
     - RTC: SDA→GPIO21, SCL→GPIO22, VCC→3.3V, GND→GND
     - SD: CS→GPIO5, SCK→GPIO18, MISO→GPIO19, MOSI→GPIO23
     - Verify SD card is inserted and formatted (FAT32)

ISSUE: Can't connect to WiFi AP
FIX: - Wait 10 seconds after button press
     - Look for "ESP32-DataLogger" network
     - Password: "12345678"
     - Try connecting manually to 192.168.4.1

ISSUE: Files not appearing in web interface
FIX: - Ensure LittleFS uploaded (pio run --target uploadfs)
     - Check data_page.html exists in data/ folder
     - Verify SD card has log files

ISSUE: Logging stops unexpectedly
FIX: - Check if LED is Megenta and flickering (SD card full)
     - Verify SD card not removed during operation
     - Check free space on SD card

ISSUE: Timestamp incorrect
FIX: - RTC battery may be dead (replace CR2032)
     - Set time using: rtc.adjust(DateTime(__DATE__, __TIME__))
     - Reflash firmware to update time

ADVANCED CONFIGURATION
════════════════════════════════════════════════════════════════════════════

Modify Config.h to adjust:

DEBUG = 1 / 0
  Toggle CSV headers on/off
  DEBUG LOG shows/dosn't show

LIGHT_SLEEP_THRESHOLD_MS
  Minimum sampling interval for light sleep (default 1000ms)

CPU_FREQ_LOGGING / CPU_FREQ_WIFI
  CPU frequencies for different modes (default 80/240 MHz)

SD_CHECK_INTERVAL_MS
  How often to check SD space (default 60000ms = 1 minute)

SD_LOW_SPACE_THRESHOLD_MB
  Free space threshold for LED OFF (default 10MB)

AP_TIMEOUT_MS
  WiFi AP timeout (default 300000ms = 5 minutes)

AP_CLIENT_GRACE_PERIOD_MS (commented out)
  Grace period after last client disconnect (optional, default 30s)
